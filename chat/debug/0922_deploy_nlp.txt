2. Per-app requirements.txt instead of the shared root one.

The repo holds many apps. Streamlit Cloud docs: it looks for the
dependency file in the entrypoint's directory first, then the repo root,
and uses only ONE (no merging). So natural_language_processing/
requirements.txt must be complete (streamlit, pandas, openai, jieba,
pypinyin, pypinyin-dict, pycccedict, opencc-python-reimplemented).
The Chinese libs were first appended to the root requirements.txt, then
moved out again so the other apps don't install them. packages.txt is
only read from the repo root.


3. Deploy failed: "error: command 'cmake' failed: No such file or directory"
   while building pyarrow (4dd5d98 fixes it).

Root cause: requirements pinned streamlit==1.51.0 (copied from the root
file), which requires pyarrow<22 -> resolver picked pyarrow 21.0.0.
Streamlit Cloud's runtime is Python 3.14.7, and pyarrow 21.0.0 has no
cp314 wheel on PyPI, only the sdist, so pip tried to compile Arrow from
source (needs cmake + Arrow C++; not in the container).

Verified, not assumed (checklist_0922.txt steps 1-3):
  - wheel METADATA: streamlit 1.51.0 -> `pyarrow<22,>=7.0`, `pandas<3`;
    streamlit 1.64.0 -> `pyarrow!=25.0.0,<26,>=7.0`, `pandas<4`.
  - PyPI file list: pyarrow 21.0.0 has no cp314 files; cp314 manylinux
    x86_64 wheels exist from 22.0.0 through 25.0.1.
  - nfl_data's debug0922.txt: streamlit==1.64.0 already deployed cleanly
    on the same Python 3.14.7 runtime.
  - Throwaway venv (local Python 3.11) with the new requirements.txt:
    resolved streamlit 1.64.0, pandas 3.0.6, pyarrow 25.0.1, numpy
    2.4.6, openai 3.19.0 -- nothing built from source. AppTest ran both
    engines with no errors (OpenAI glossed 靈 as "spirit").
    Not tested locally: Python 3.14 itself (not installed); covered by
    the nfl_data deploy above.

Fix: streamlit==1.51.0 -> streamlit==1.64.0 in
natural_language_processing/requirements.txt. No app code changed.
Redeploy succeeded.

Not done, deliberately:
  - Redeploying on Python 3.12 (works too, but only moves the problem;
    the pin fix works on the current runtime).
  - Loosening to `streamlit>=1.51` (pasted suggestion) -- a floating pin
    can resolve differently on the next rebuild; 1.64.0 is the version
    already proven on this runtime.
  - Adding cmake to packages.txt -- Arrow C++ is also needed, and a
    from-source build would be slow and likely hit memory limits.

What to expect in future deploy logs: `+ streamlit==1.64.0` and pyarrow
>= 22. Streamlit Cloud may swap pyarrow 25.0.1 for 24.0.0 on its own
(seen in nfl_data's requirements.txt deploys) -- expected, not an error.
